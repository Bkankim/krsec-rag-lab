# 리랭커 실험 (`rerank`)

결과: 주 트랙(공개)은 `hypothesis-rejected`, 보조 트랙(KISA)도 `hypothesis-rejected`다. 사전 등록한 설정으로 test를 한 번 돌렸고 결과를 본 뒤 설정·가설·판정 규칙을 바꾸지 않았다. 하네스 계약은 [README.md](README.md), 판정 규칙의 정본은 런 스펙 이슈 #43의 "실험 공통 규칙"이다. 형식은 [hybrid.md](hybrid.md)를 따른다.

## 1. 가설 (사전 등록)

- 가설: cross-encoder 리랭커(`BAAI/bge-reranker-v2-m3`, revision 고정)로 BM25 상위 N건을 다시 정렬하면, 같은 후보군의 BM25 순서보다 test macro nDCG@10이 높다.
- 주 트랙: 공개 트랙, 기준 = `results/baselines/public/bm25.jsonl`. KISA 트랙(기준 = `results/baselines/kisa/bm25.jsonl`)은 같은 규칙의 보조 판정이다. 이슈 라벨은 주 트랙 판정을 따른다.
- 판정: test macro nDCG@10의 `delta = 실험 - 기준`이 0보다 크고, 유형별 층화 paired bootstrap(10000회, 시드 `20261029`) 95% 구간의 하한이 0보다 크면 `hypothesis-confirmed`, 그 밖은 `hypothesis-rejected`.

## 2. 구성

- 후보군(동일 후보군): 기준선 manifest에 확정된 트랙별 BM25 설정(공개 k1=1.2, b=0.75; KISA k1=3.0, b=0.9)과 `bm25-tok-v1` 토큰화로 이 실험이 **다시 계산한** BM25 전체 순위(unjudged 제거 전, 질의 토큰이 하나라도 든 문서만)의 상위 N건이다. 저장본 상위 100건으로 후보를 만들지 않는다. 리랭커는 그 집합 안의 순서만 바꾸고 후보를 더하거나 빼지 않는다. N 밖 문서는 BM25 순서 그대로 N건 뒤에 두고, 후보가 N 미만이면 그만큼만이다. 그래서 recall@N은 기준과 같고 바뀌는 것은 순서뿐이다.
- 리랭커: `BAAI/bge-reranker-v2-m3` revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`, sentence-transformers `CrossEncoder`, CPU, 활성화 함수 없음(점수 = 로짓 원점수), 배치 16. 입력은 (질의 문자열 그대로, 색인 텍스트 그대로) 쌍이고 지시문 접두사가 없다. 최대 길이는 기본값 512 토큰이고 바꾸지 않았다(초과분은 문서 쪽이 절단된다). 질의 인코딩과 달리 문서를 미리 색인하지 않으므로 질의마다 후보 N건을 모델에 통과시킨다.
- 점수: 후보 N건은 리랭커 원점수를 그대로 쓰고, N 밖 문서는 `min(후보 점수) - 1 - BM25 순위 x 1e-6`을 받는다(BM25 순서를 유지하고 모든 후보보다 엄격히 작다). 그래서 `top1_score_raw`는 리랭커 원점수 1위다. 점수가 같으면 문서 ID 오름차순이고, unjudged 제거와 상위 100건 저장은 기준선과 같은 공통 채점 코드가 한다.
- N: 격자 {20, 50, 100}에서 트랙마다 dev macro nDCG@10이 가장 큰 값. 같으면 작은 N. N이 같은 후보를 만드는 경우(BM25 일치 문서가 N 이하)가 많아 동점이 흔하다.
- τ(no_answer 기권 임계값): 기준선과 같은 규칙(dev에서 abstain_rate - false_abstain_rate 최대, 같으면 가장 낮은 τ)으로 리랭커 점수 1위(원점수)에 대해 dev에서 고른다. BM25 일치 문서가 없는 질문은 결과가 비어 있어 τ와 무관하게 기권으로 센다.
- 하이브리드 후보군 위의 리랭킹, 다른 리랭커 모델 비교, 청크 단위 리랭킹은 이 실험 범위 밖이다.

## 3. 재현 명령

`<KISA-ROOT>`는 KISA 캐시(`data/kisa`)가 있는 체크아웃이다. 모델이 필요한 실행은 `embed` 그룹을 쓴다. 측정은 `OMP_NUM_THREADS=4`로 했다.

```
uv sync --locked --group embed
OMP_NUM_THREADS=4 uv run --no-sync python scripts/run_experiment.py --exp rerank --track public --split dev   # N, tau 선택(몇 번 돌려도 됨)
OMP_NUM_THREADS=4 uv run --no-sync python scripts/run_experiment.py --exp rerank --track public              # dev 선택 뒤 test 1회
OMP_NUM_THREADS=4 uv run --no-sync python scripts/run_experiment.py --exp rerank --track kisa --kisa-root <KISA-ROOT>
uv sync --locked --dev
uv run python scripts/run_experiment.py --exp rerank --compare   # 모델·KISA 캐시 없이 저장본에서 metrics·comparison을 다시 계산해 대조(불일치 exit 1)
```

산출물: `results/experiments/rerank/{public,kisa}/rerank.jsonl`, `manifest.json`, `metrics.json`, `comparison.json`. test 설정 해시는 manifest의 `runs[<track>/rerank].test.config_hash`다.

측정 환경: Apple M5 Pro, 18코어, `OMP_NUM_THREADS=4`, CPU 추론. 같은 맥에서 다른 작업이 함께 돌았을 수 있어 참고값으로만 읽는다.

|---|---|---|---|
| public | BM25 | 0.010 | 0.000005 |
| public | 리랭커(BM25 + 후보 N=50 쌍 채점) | 3.062 | 0.088670 |

리랭커의 색인 시간은 BM25 색인, 모델 적재, 코퍼스 토큰화(문서 길이 집계)를 합친 값이다(코퍼스 인코딩은 없다). 질의 지연은 질의마다 후보를 모델에 통과시키는 비용이고 후보가 많고 문서가 길수록 커진다(KISA는 문서가 길어 질의당 수 초다). 지연은 dev 선택 단계의 선택 N 실행과 test 질문 전체의 중앙값이다.

절단(최대 512 토큰, 값은 manifest의 `description`):

| 트랙 | 코퍼스 문서 수 | 질의가 비어 있어도 잘리는 문서 수 | 문서 최대 토큰 | 채점한 쌍 수 | 잘린 쌍 수 |
|---|---|---|---|---|---|
| public | 1560 | 1 | 515 | 2204 | 2 |
| kisa | 50 | 27 | 22747 | 1028 | 368 |

"채점한 쌍"은 이 실행이 선택한 N으로 채점한 질문 전체(공개 144건, KISA 52건: dev와 test 합산)의 (질의, 후보 문서) 쌍이다. 쌍의 토큰 수는 질의 + 문서 + 특수 토큰이 512를 넘으면 잘린 것으로 센다(질의가 짧아 문서 쪽이 잘린다). 공개 트랙 문서는 거의 짧다. KISA 공지 50건 중 27건은 질의가 비어 있어도 잘리는데 이는 하한이고(질의와 짝지을 때 잘리는 서로 다른 문서 수는 세지 않았고 더 많을 수 있다), 실제 채점한 쌍 기준 절단은 368/1028(35.8%)이다.

## 5. 판정

- **주 판정(공개 트랙): `hypothesis-rejected`.** delta +0.0030은 양수지만 95% 구간 [-0.0206, +0.0244]의 하한이 0 이하라 BM25 순서보다 높다고 주장할 수 없다.
- **보조 판정(KISA 트랙): `hypothesis-rejected`.** delta +0.0000, 95% 구간 [-0.0738, +0.0738]. 하한이 0 이하다.
- 결과가 가설을 기각해도 정상 종료다. 이슈 라벨은 `comparison.json`의 `primary.verdict`대로 `hypothesis-rejected`다.

### 6.3 원인

**공개 트랙**

- 확인: 정답이 있는 test 질문 74건 중 `cve_explicit` 35건은 BM25 저장 결과가 모두 1건이다(CVE ID 토큰이 문서 하나에만 일치). 리랭커가 순서를 바꿀 후보가 하나뿐이라 nDCG@10은 구조적으로 1.0 그대로이고 이 유형은 리랭커로 바뀔 수 없다.
- 확인: `product_symptom` 39건 중 5건은 BM25 결과가 비어 있어(정답 도달 불가) 리랭커가 후보를 더할 수 없으므로 개선도 악화도 없다. 1건은 후보가 1건이다. 나머지 33건이 순서를 바꿀 여지가 있는 질문이다(후보 2~50건 8건, 저장 결과가 50건 초과 25건). test 정답 질문 74건 중 BM25 상위 50건 안에 정답이 없는 질문은 2건, 결과가 빈 질문은 5건이다.
- 확인: 상위 10건의 순서가 바뀐 정답 질문은 33건인데 nDCG@10이 바뀐 것은 10건(개선 6, 악화 4)이다. macro hit@10 delta는 +0.0000인데, 이는 첫 정답이 상위 10건 경계를 넘은 두 질문(`pub-prod-0047`: 3위에서 15위, `pub-prod-0038`: 17위에서 4위)이 서로 상쇄한 값이다: `pub-prod-0047`은 첫 정답이 3위에서 15위로 밀려 hit@10이 1에서 0이 됐고, `pub-prod-0038`은 17위에서 4위로 올라 0에서 1이 됐다(둘 다 `product_symptom`이라 유형 hit@10 delta도 +0.0000). 나머지 질문의 hit@10은 그대로다. 상위 10건 안의 정답 수는 `pub-prod-0015`(9건에서 6건), `0030`(9건에서 10건), `0033`(9건에서 10건), `0038`(0건에서 1건), `0047`(2건에서 0건), `0060`(7건에서 9건)에서 달라졌다.
- 확인: 악화 4건 중 `pub-prod-0009`(정답 1건)는 BM25 1위였던 정답이 리랭커 4위가 됐다. `pub-prod-0015`(정답 45건)는 첫 정답은 1위 그대로인데 상위 10건 안 정답 수가 9건에서 6건으로 줄었다. `pub-prod-0047`(정답 16건)은 BM25 3위·7위였던 정답이 15위·18위로 밀려 상위 10건 안 정답이 2건에서 0건이 됐다. `pub-prod-0042`는 8위에서 9위다.
- 확인: 개선은 `pub-prod-0038`(BM25 결과가 29건이라 후보가 N=50 미만, 정답 17위 -> 4위), `pub-prod-0035`(7위 -> 2위)처럼 정답이 1건인 질문과, 정답이 49~56건인 `pub-prod-0030`, `pub-prod-0060`, `pub-prod-0033`에서 상위 10건 안 정답 수가 7~9건에서 9~10건으로 늘어난 경우다.
- 추정: 리랭커는 악화 질문 일부(`pub-prod-0009`, `pub-prod-0047`)에서 BM25가 이미 1~3위에 올린 정답을 내렸고 개선 질문 일부에서는 반대로 올렸다. 순 효과가 0에 가까운 것은 두 방향의 변화가 비슷한 크기로 상쇄됐기 때문으로 보이며, 문서 본문을 보지 않았으므로 정답이 내려간 이유(영문 설명의 어떤 표현을 리랭커가 덜 관련 있다고 본 것인지)는 확인하지 못했다.
- 확인: dev에서는 리랭커(N=50, 0.8703)가 BM25(0.8533)보다 +0.0170 높았고 test에서는 +0.0030이다. 방향은 같고 크기가 줄었다. 추정: 표본 변동이고 한쪽 분할의 결과로 우열을 주장하기 어렵다.

**KISA 트랙**

- 확인: test 정답 질문 23건 중 BM25가 1위에 정답을 둔 질문이 21건이다. 기준이 이미 0.9451이라 올릴 여지가 작다. 상위 10건 순서가 바뀐 질문은 23건 전부인데 nDCG@10이 바뀐 것은 2건(`g1-ec-03` 악화, `g1-ec-10` 개선)이고 두 변화의 크기가 같아(±0.3691) delta가 정확히 0이다. 이 0은 두 질문의 효과가 상쇄된 값이고, 두 질문 외에는 변화가 없다는 뜻이다.
- 확인: 두 질문 모두 `explanation_comparison`(n_scored 5, 관찰로만 읽는다)이고 정답 1건의 순위가 1위와 2위 사이에서 바뀌었다. `cve_explicit`(11건)과 `product_symptom`(7건)은 변화가 없다.
- 확인: KISA 문서 50건 중 27건은 512 토큰 한도에서 질의가 비어 있어도 잘린다(하한, 최대 22747 토큰). 실제 채점한 쌍 기준으로는 35.8%(368/1028)가 잘렸다. 리랭커는 문서 앞부분 512 토큰만 본다.
- 추정: 절단이 KISA에서 리랭커의 이득을 가로막았을 수 있지만, 이 실험은 절단 길이를 바꾼 대조가 없어 효과의 크기를 확인하지 못한다.
- 확인: dev에서는 리랭커(N=20, 0.9616)가 BM25(0.7970)보다 +0.1646 높았는데 test에서는 +0.0000이다. dev 기준선이 0.7970으로 낮아 올릴 여지가 컸고 test 기준선은 0.9451이다. 같은 설정으로 test를 한 번만 돌았으므로 이 차이를 보고 설정을 바꾸지 않았다. 추정: dev와 test의 난이도 차이와 표본 변동(dev 정답 질문 19건 안팎, test 23건)이고, 어느 쪽이 대표적인지는 이 표본으로 알 수 없다.

## 7. 한계

- 질문 단위 재표집은 test 안 질문끼리의 의존(같은 공지·CVE를 쓰는 질문)을 독립으로 다뤄 구간을 실제보다 좁게 낼 수 있다. dev와 test 사이는 eval-protocol 6절의 그룹 분할로 이미 분리돼 있다.
- 리랭커가 순서를 바꿀 수 있는 질문이 적다. 공개 트랙은 `cve_explicit` 35건이 후보 1건이고 `product_symptom` 5건은 BM25 결과가 비어 있고 1건은 후보가 하나라 74건 중 41건(`product_symptom` 후보 1건 포함)은 구조적으로 바뀔 수 없다. 이 실험은 BM25가 후보를 낸 질문에서의 순서 효과만 잰다. 후보군이 BM25 상위 N건으로 고정이라 BM25가 놓친 정답은 리랭커로 구제하지 못한다(공개 test 정답 질문 중 결과가 빈 5건, 상위 50건 밖 2건; 이 한계가 "동일 후보군" 설계의 비용이다).
- KISA 트랙 test는 정답이 있는 질문 23건이고 `product_symptom`(7건), `explanation_comparison`(5건)은 n_scored < 10이라 유형별 우열을 주장할 수 없다. 구간이 넓다([-0.0738, +0.0738]). 어느 방향의 효과도 이 표본으로는 확인하지 못한다.
- KISA 문서 50건 중 27건은 질의가 비어 있어도 512 토큰을 넘어 앞부분만 리랭커에 들어간다(하한). 실제 채점한 쌍 기준 절단은 368/1028(35.8%)이다. 절단 길이를 달리한 대조(예: 더 긴 최대 길이, 문서 앞·뒤 발췌)는 하지 않았다. 공개 트랙의 절단은 2쌍뿐이라 영향이 거의 없다.
- 첫 정답 순위는 저장된 상위 100건 안의 순위다. "범위 밖"은 전체 순위에서 미검색인지 단지 100위 밖인지 구분하지 못한다.
- N 격자는 3개 값이고 공개에서 N=50과 N=100이 같은 dev 값이라 N 선택이 사실상 둘 중 하나다. 선택은 규칙대로 했지만 이 격자 안의 N 사이에서 test 결과가 안정적이라고 확인한 것은 아니다. test는 선택한 N 하나만 돌았다. KISA는 N=20이 선택돼 후보가 가장 적다.
- τ는 리랭커 로짓 척도에 대해 dev에서 고른 값이고, no_answer 질문은 공개 12건, KISA 6건이라 기권율은 거친 값이다. BM25와 척도가 다른 τ를 직접 비교하지 않는다.
- 리랭커 로짓을 그대로 쓰므로 sigmoid 같은 변환은 순위에 영향이 없지만 τ 값에는 영향이 있다. 이 실험은 로짓만 측정했다.
- 질의 지연과 색인 시간은 참고값이다. 다른 작업과 같은 맥에서 병렬로 돌았을 수 있고 CPU 추론이다. 지연 중앙값은 dev(선택 N 실행)와 test를 합친 질문의 값이다.
- `selected_n_usage`(채점한 쌍 수, 잘린 쌍 수)와 절단 문서 수는 `--compare`로 저장 결과에서 다시 계산할 수 없는 manifest `description` 값이다.
- 이 결과는 "BM25 후보군 위의 `bge-reranker-v2-m3` 하나"에만 해당한다. 하이브리드 후보군, 다른 리랭커, 청크 단위 리랭킹은 측정하지 않았다.
- test는 확정 설정으로 한 번 돌았다. 같은 설정으로 빈 `--out-dir`에 두 트랙을 다시 돌린 재현 실행은 두 트랙의 `rerank.jsonl`과 `metrics.json`이 커밋된 파일과 바이트까지 같았고(`comparison.json`은 참고값인 색인 시간·지연만 달랐다), 이 보고서의 숫자는 커밋된 첫 실행을 기준으로 한다.
